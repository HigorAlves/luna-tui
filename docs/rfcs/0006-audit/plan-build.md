## Top gaps by impact

1. **No entry contract check before Build (B2-B5).** Build starts with no plan version, any number of scenarios (zero included), with or without a map, and never reads the risk. With no planned files at all, `scopeFacts` reports nothing as undeclared (`machine/src/domain/scope.ts:112`), so the scope gate is silently off.
2. **No change-size guard (P15-P17).** `est_loc` is collected and read only by the retro. No limit, no split, no route back to ticket decomposition: an XL ticket is planned and built as one change.
3. **Sandbox is not the diagram's (B6, B8, B9, B11, B12, B14).** Unrestricted network egress for a writable agent, 2 CPU / 4 GB, no token budget, a shared image rather than the project's, dependencies installed by the agent, no `env_hash` recorded: a build is not reproducible and the network boundary is the default bridge.
4. **Tests-first is not its own step and tests are not tied to scenarios (B16, B18, B19, B24, B25).** One test per slice, no `@scenario:id`, no tests-only commit, no checkpoint after red, and the ledger lets a slice reach `committed` without a red. Nothing downstream can check "every approved scenario has a test that failed first".
5. **Risk is computed differently and too late (P12, P14, P39).** Sum instead of product changes the level for (1,1,3), (2,2,1), (3,3,1); it runs after the plan and the plan check, so neither the planner nor "risk-appropriate" can use it.
6. **The test designer reads the plan's steps (P24) and scenarios have no structure (P25).** Scenarios are no longer independent of the plan, and without id, type, given/when/then or layer, coverage can only be matched by exact criterion text.
7. **`plan_wrong` returns to triage without its evidence (B59).** The reason is on the transition event only; the next triage and plan prompts never see it.
8. **Coverage gate is by string match, not by a score (P27-P29).** A scenario that names a criterion closes the gap whatever it tests; `coverage_check` saying "does not pin" only flags the gate.
9. **Budget and escalation do not behave as drawn (B31-B33, B47, B53, B54).** No iteration or token counters; a scope failure or a timeout is a silent re-run up to six times; `undeclared_scope` and `env_broken` are never emitted by the machine; the escalation reason is the agent's own word, not a typed decision.
10. **No Build Report and none of the diagram's events (B65, B67-B71, P49).** No `card.*` or `build.*` events, no test list before/after, no tokens, no env hash; a consumer must reconstruct them from `transition` events and run details.

Also notable: the plan gate cannot override risk or the code map and stores no reason (P43, P47); "one approver outside the owning team" and "5d escalate" are not built (P33, P34); the fast lane pays for the full code map and its impact queries (P56); the final push is never squashed and carries no card link or plan version (P48, P49); the human pick-up has no kept sandbox and the checkpoint sits on a ref a plain fetch does not bring (B60, B61).
