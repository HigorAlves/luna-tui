## The config shape
```yaml
checks:                      # the repo's own checks; order them fast to slow
  - name: machine tests      # a short label the board shows
    run: pnpm test           # one shell line, as a maintainer types it
    cwd: machine             # where to run it; omit for the repo root
    paths: ["machine/**", "contracts/**"]   # run only for a change under these; omit to always run
services:                    # what the code needs beside it; key = hostname
  postgres:
    image: postgres:16
    env: { POSTGRES_USER: app, POSTGRES_PASSWORD: app, POSTGRES_DB: app }
    ready: pg_isready -U app # run inside the service until it exits 0; omit when the image needs no wait
    exports: { DATABASE_URL: "postgres://app:app@postgres:5432/app" }   # env the checks and stages get
toolchains: { node: "24", rust: "1.99" }
policy: { qa: web }          # only keys the tree states: qa, monthly_budget_usd, auto_approve_plan_minutes, max_concurrent, holdout_cases
qa_targets: []               # only documented targets: { name, url, credential: env:NAME }
verify:
  e2e:
    start:                   # how the browser check starts the app from the card's branch; only for a repo that renders a page
      command: "pnpm --filter web dev --hostname 0.0.0.0 --port 3000"   # bound to 0.0.0.0: the browser runs in another container
      port: 3000
      ready: /               # the path that answers once the app is up
      ready_timeout_s: 180
sandbox:
  egress:
    allow: [index.crates.io, static.crates.io]   # hosts a check or the app reaches that the machine's list misses (below)
```

**The app start** (`verify.e2e.start`): find the dev or start script of the package that serves the pages (a `dev`/`start` script, a framework config), and bind it to `0.0.0.0` with the framework's own flag (`--hostname`, `--host`, `-H`). No page to render (a library, a CLI, a service with no UI): leave it out and set `policy.qa: none`.

**Egress** (`sandbox.egress.allow`): every check and the app run behind a proxy that lets out only GitHub and the package registries of the repo's lockfiles (a tracked one in a subfolder, like `board/Cargo.lock`, adds its ecosystem's public registry; a custom registry it names does not). List what else they reach: a custom registry a subfolder's lockfile names, a tool a script fetches (corepack fetches pnpm from `registry.npmjs.org`), fonts or assets the app loads at build time (`fonts.googleapis.com`, `fonts.gstatic.com`). Only hosts the tree shows a need for; the proof names any host a check was refused, for the person to add.

Every key is optional. A `run` line goes through `sh -c` in `cwd`, in a container built from the stage image (Node 24, Go, Rust, git, gh; no Docker inside). The machine then runs every check once with the services beside it and shows the person pass or fail per check.
